# ReformANY — brand and product principles

**Owner / publisher:** Acev Dev Co  
**Product name:** ReformANY  
**Quick-access feature:** ReformANY Orbit  
**Product line:** Convert anything. Effortlessly.

## Identity

ReformANY should be recognizable through restraint, not decoration. A quiet, professional Windows desktop product with clear hierarchy, considered spacing, precise controls and dependable outcomes.

The tagline is an expression of the product's ambition, **not** a claim that arbitrary file formats can be converted into one another. Marketing must state actual supported routes and engine requirements.

## Visual direction

- **Logo:** use the current official ReformANY mark already in the repository. Do not substitute AI-generated icons, competitor marks or old-project artwork. Preserve aspect ratio and breathing room.
- **Palette:** dark ink and graphite neutrals, calm light surfaces, and a single muted sage-green accent that matches the current Orbit and app controls. Avoid multicolor gradients, translucent card stacks and ornamental glows.
- **Typography:** favor legible, properly licensed system typography such as Segoe UI Variable on Windows. Use consistent weight, line-height and tracking. Do not redistribute proprietary fonts without rights.
- **Layout:** simple navigation, generous negative space and a small number of meaningful surfaces. Keep forms, indicators and alerts predictable. Avoid decorative cards that communicate nothing.
- **Orbit:** a genuinely circular, compact desktop shortcut, divided into Convert, Tools and Actions. Mouse hover, keyboard accessibility and optional subtle locally synthesized audio should feel immediate, not flashy.
- **Installer:** a dark, still, branded NSIS setup. The real installation progress indicator and a clear Launch ReformANY completion option matter more than animation.
- **Motion:** only where it clarifies state. Honor reduced-motion and keyboard accessibility preferences. No background decorative loops.

## Writing and public presentation

Use direct labels: **Choose file**, **Convert**, **Show result**, **Cancel**, **Ready**. Explain limits before a conversion rather than reporting them after failure. Avoid unverified phrases such as “all formats,” “zero errors,” “most secure,” “lossless” or “fastest.”

Trust comes from inspectable code, accurate format documentation, a verified build, transparent dependencies and clearly stated privacy rules—not an oversized feature list or fake testimonials.

## Release and marketing artwork

Use actual application captures from a tested Windows build, with permission to publish any sample content shown. Show the actual image workspace, an independent Orbit window, a scrollable multi-page PDF and the dark installer. Do not publish synthetic UI mockups as evidence of shipped functionality.

Any future logo motion or loading animation must be designed as a separate approved first-party asset. No inherited GIFs or older product assets.
